## Известные проблемы

Среда разработки (проверено командами, см. `docs/questions.md`, Q1):

1. **Go собран под 386** (`go1.27.0 windows/386`). Следствие уже наступило: `go test -race` отвечает `-race is not supported on windows/386`. Значит требование `go test -race ./...` из `CLAUDE.md`, п. 5 на этой машине **невыполнимо**. Нужен `windows/amd64` или Go внутри WSL2.
2. **Docker не запускается**: демон не отвечает, WSL не установлен. Блокирует шаги 0.2, 0.4, 0.5 и все интеграционные тесты на настоящем PostgreSQL.
3. **Нет `make`** — цели приходится запускать вручную.
4. **Проект лежит в OneDrive, в пути есть пробел.** OneDrive синхронизирует `.git`, а дальше появится и `node_modules`.
5. Удалённого репозитория нет, CI поднять не на чем (Q2).

## Решения, принятые по умолчанию

Отменяются ответом человека; записаны, чтобы не выглядели обдуманным выбором.

1. **Имя модуля Go — `docflow`** (без домена и владельца), потому что Q2 не отвечен. При переезде на GitHub меняется одной заменой по всем импортам.
2. **Пакет каталога `internal/http` назван `httpapi`**: пакет с именем `http` перекрывал бы стандартный `net/http` в каждом файле.
3. **`/healthz` и `/readyz` открыты без аутентификации**, но наружу не отдают причину отказа — её видно только на служебном адресе с показателями.
4. **Идентификатор обращения из заголовка `X-Request-Id` принимается**, но очищается от управляющих символов. Предполагается, что nginx его перезапишет.
5. **Двенадцать цифр подряд в журнале всегда скрываются.** ИИН и БИН по виду неразличимы, поэтому под маску попадает и БИН: в логах вместо него уместен `company_id`.
6. **Добавлена зависимость `prometheus/client_golang`**, которой нет в перечне стека, — показатели требует этап 0 роадмапа. ADR будет написан на шаге 0.13.
